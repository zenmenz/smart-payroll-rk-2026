# Спецификация Smart Payroll РК

**Версия:** 1.0.0  
**Статус:** Серверная основа готова; база данных намеренно не содержит начальных записей.  
**Назначение:** Документ определяет контракты backend, модель данных, правила доступа и назначение существующих элементов интерфейса. Подключение новых экранов и дополнительных элементов выполняется отдельным этапом по запросу владельца.

> **Ограничение дизайна.** Исходная компоновка, палитра, типографика, размеры и существующие визуальные элементы перенесены без стилистических изменений. Новые страницы и элементы на данном этапе не добавлялись.

## 1. Роли и доступ

| Роль | Доступ к данным | Разрешённые операции |
|---|---|---|
| `admin` | Все организации и все кадровые данные | Управление сотрудниками, справочниками, профилями ставок, периодами, строками начислений, расчётами, статусами, экспортом, настройками компании и аудитом. |
| `user` | Только собственная кадровая карточка и связанные расчётные листки | Просмотр собственных листков после того, как администратор привяжет учётную запись к сотруднику. |

Владелец проекта автоматически получает роль администратора при первой авторизации. Обычный пользователь не может вызвать административные процедуры: сервер возвращает ошибку `FORBIDDEN` ещё до чтения payroll-данных.

## 2. Таблицы базы данных

| Таблица | Назначение | Ключевые поля и ограничения |
|---|---|---|
| `employees` | Карточки сотрудников | ФИО, ИИН (уникальный), оклад, дата приёма, статус, банк, IBAN, вычеты, применимость ОПВР, связь с учётной записью. |
| `departments` | Справочник подразделений | Уникальный код, наименование, признак активности. |
| `positions` | Справочник должностей | Уникальный код, наименование, необязательная ссылка на подразделение. |
| `accrualTypes` | Типы начислений и удержаний | Код, название, вид `accrual` или `deduction`, признак налогооблагаемости. |
| `taxProfiles` | Версионные профили налогов | Дата действия, МРП, МЗП, ставки в базисных пунктах, пределы базы и параметры корректировок. |
| `payrollPeriods` | Расчётные периоды | Уникальный ключ `ГГГГ-ММ`, месяц, год, статус `open`/`closed`, выбранный профиль ставок. |
| `employeePayrollItems` | Ручные строки периода | Сотрудник, период, тип начисления/удержания, сумма, комментарий. |
| `payrollCalculations` | Снимки расчётов и расчётные листки | Полный набор сумм, статус выплаты, снимок применённого профиля ставок, дата и оператор расчёта. Уникальность: сотрудник + период. |
| `companySettings` | Реквизиты работодателя | Юридическое название, БИН, адрес; добавляются владельцем позже. |
| `auditLogs` | История действий | Оператор, сущность, действие, описание, дата и время. |

Все денежные значения хранятся в целых тенге. Это исключает ошибки двоичной дробной арифметики при суммировании расчётных листков.

## 3. Функциональные процедуры backend

| Группа | Процедура | Роль | Назначение |
|---|---|---|---|
| Справочники | `payroll.references.list` | `admin` | Получить подразделения, должности, типы начислений и профили ставок. |
| Справочники | `payroll.references.*.create/update` | `admin` | Создавать и редактировать записи справочников и профили ставок. |
| Сотрудники | `payroll.employees.list/create/update/archive/delete` | `admin` | Управлять карточками сотрудников; удаление запрещается, если есть расчётная история. |
| Периоды | `payroll.periods.list/create/close/reopen` | `admin` | Создавать, закрывать и повторно открывать месяцы. |
| Начисления | `payroll.payroll.upsertItem/deleteItem` | `admin` | Вести дополнительные строки сотрудника только в открытом периоде. |
| Расчёт | `payroll.payroll.calculatePeriod` | `admin` | Рассчитать всех активных сотрудников периода, сохранить снимок профиля ставок. |
| Журнал | `payroll.payroll.journal` | `admin` | Фильтровать расчёты по периоду, подразделению, сотруднику и статусу выплаты. |
| Статус | `payroll.payroll.updateCalculationStatus` | `admin` | Перевести расчёт в `draft`, `verified`, `approved` или `paid` в открытом периоде. |
| Листки | `payroll.payroll.myPayslips` | `user`/`admin` | Вернуть расчётные листки связанного сотрудника без доступа к чужим данным. |
| Дашборд | `payroll.dashboard.summary` | `admin` | Вернуть ФОТ, количество сотрудников, сумму налогов/взносов и число расчётов. |
| Экспорт | `payroll.reports.exportJournal` | `admin` | Подготовить файл журнала в `csv` или `xlsx` как Base64-пакет. |
| Настройки | `payroll.company.get/save` | `admin` | Прочитать или сохранить реквизиты работодателя. |
| Аудит | `payroll.audit` | `admin` | Получить историю значимых операций. |

## 4. Правила расчёта

Расчётный движок не хранит ставки в коде. Для вычисления нужен профиль `taxProfiles`, выбранный в расчётном периоде. Если профиль отсутствует, пересчёт останавливается с понятной ошибкой конфигурации; это предотвращает начисление по неутверждённым параметрам.

| Шаг | Правило |
|---|---|
| Доход | `gross` равен окладу плюс облагаемые и необлагаемые дополнительные начисления. |
| ОПВ и ВОСМС | Рассчитываются с облагаемого дохода с учётом предельной базы профиля. |
| ИПН | База уменьшается на ОПВ, ВОСМС, разрешённые вычеты и корректировку дохода; поддержаны базовая и повышенная годовые шкалы. |
| СО | Рассчитываются с ограничением минимальной и максимальной базы профиля. |
| ООСМС, СН, ОПВР | Рассчитываются по профильным ставкам и пределам; ОПВР можно отключить для конкретного сотрудника. |
| Снимок | Результат и полный профиль ставок сохраняются в `payrollCalculations`. Изменение будущего профиля не меняет закрытые листки. |

В профиле ставок уже предусмотрены параметры для 2026 года, но сами записи намеренно не создаются. При заполнении справочника бухгалтер должен подтвердить применимые значения; официально опубликованы МЗП 85 000 тенге и МРП 4 325 тенге с 1 января 2026 года, а ОПВР в 2026 году составляет 3,5 %.[1] [2]

## 5. Существующие кнопки и элементы интерфейса

| Элемент | Текущее назначение | Backend-контракт для последующего подключения |
|---|---|---|
| **Excel** | Визуальная точка экспорта в исходном макете | `payroll.reports.exportJournal` с форматом `csv` или `xlsx`. |
| **Листки** | Визуальная точка показа расчётных листков | `payroll.payroll.myPayslips` для сотрудника; `payroll.payroll.journal` для администратора. |
| **Сотрудник** | Визуальная точка создания карточки | `payroll.employees.create`; дата приёма и связь с пользователем остаются полями будущей формы. |
| **Статус ведомости** | Визуальный рабочий поток | `payroll.payroll.updateCalculationStatus`; закрытие месяца — `payroll.periods.close`. |
| **Селектор периода** | Выбор отображаемого месяца | `payroll.periods.list` и `payroll.periods.create`. |
| **Таблица сотрудников** | Отображение кадров и сумм | `payroll.employees.list` и `payroll.payroll.journal`. |
| **Поиск и фильтры** | Фильтрация списка | Параметры `query`, `departmentId`, `status`, `periodId`, `employeeId`. |
| **Журнал аудита** | Отображение истории действий | `payroll.audit`. |

## 6. Сценарий первичного наполнения

Администратор сначала создаёт справочники подразделений, должностей, типов начислений и утверждённый профиль ставок. Затем создаются сотрудники и выбранный расчётный период. После добавления дополнительных строк начислений запускается расчёт периода, результаты проверяются, переводятся по статусам и при необходимости экспортируются. Карточка сотрудника может быть связана с учётной записью для доступа к собственным листкам.

## 7. Проверка качества

В проекте добавлены модульные тесты расчётного движка, проверки доступа, пустого состояния сотрудника, CSV/XLSX-экспорта и выхода из сессии. Production-сборка проходит успешно. Демонстрационные записи из предоставленного архива не переносятся в базу и не отображаются в приложении.
